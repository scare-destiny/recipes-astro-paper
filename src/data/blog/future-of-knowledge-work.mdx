## The evidence: expertise beats syntax

{/*
- Anthropic research, "Agentic coding and persistent returns to expertise":
  https://read.readwise.io/read/01kvmth42ndwtyf0gjg1n2hvx8
  - Domain experts reach verified success 2x+ more often than novices.
  - Division of labor: "People decide what to build, the agent decides how."
  - Success is determined by how well you understand the problem, not whether
    you're trained in coding.
  - Competence captures most of the benefit; deep mastery adds only a bit more.
- Implication: agents don't substitute for domain expertise — they amplify it.
- Google SDLC paper says the same thing from the other side ("the shift from syntax
  to intent"): the skills that matter now are decomposition, evaluation, and system
  design — and "context engineering" (feeding agents your domain knowledge, codebase
  conventions, guardrails) is "the real skill." Two independent sources, one conclusion.
- Conductor vs orchestrator (Google's framing): real-time pair-programming vs async
  multi-agent delegation. The orchestrator role is knowledge work's new shape.
- Founder's Playbook angle (secondary): turning domain knowledge into AI context is
  the compounding moat. https://read.readwise.io/read/01kv5zct2z2r53zeygtwxghyac
*/}

## The new bottleneck: the loop, not the code

{/*
- "The costliest thing in AI coding is no longer writing code, it's managing the
  agent loop." https://read.readwise.io/read/01kv5zc566ky9fcjagecze1860
- Knowledge work is becoming: define the task, design the loop, verify the output,
  know when to stop it.
- Google SDLC paper reinforces this with two ideas worth borrowing:
  - The "factory model": the developer's primary output is not code — it's the
    system that produces code (specs, agents, quality gates, feedback loops, guardrails).
  - "Most agent failures, examined honestly, are configuration failures" — one team
    went from outside Top 30 to Top 5 on Terminal Bench by changing only the harness,
    no model change. Blaming the model is usually wrong.
  - The "80% problem": agents generate 80% fast; the last 20% (edge cases, business
    logic, integration) demands deep contextual knowledge — exactly where domain
    expertise pays.
- My lived example (one paragraph, concrete, not a tool list): running production
  agents means an eval harness across quality dimensions, observability, and
  per-provider cost control — the unglamorous work that makes agents shippable.
- Loops that survive restarts / run on schedules are an infrastructure problem:
  https://read.readwise.io/read/01kw7bxs87yr4jvvnpb3188293
*/}

## The first job built for this era: the forward deployed engineer

{/*
- Andrew Ng, The Batch: FDE is the buzzy new Silicon Valley job; OpenAI and
  Anthropic are building teams to embed FDEs in client orgs.
  https://read.readwise.io/read/01kssjsaxgk99zst17tvn40cz2
- Origin: Palantir, two decades ago — engineers shipped code overnight next to
  Special Forces in Afghanistan. You can't build for an environment without being in it.
- Job anatomy: audit → evals → deployment.
  https://read.readwise.io/read/01kv5zd1n62k4b58q5estvctg6
- The deal-breaker skill isn't coding — it's explaining to a non-technical VP what
  AI can and can't do. No communication, no deployment.
- Why now: if intelligence is commoditized, the only edge is how and where you use it.
*/}

## My take: hybrid is the new senior

{/*
- The thesis. For years my path looked unfocused: PR degree, sales, running an
  agency (presales, scoping, closing), growth marketing, then engineering.
  The market called it scattered. Now it's the exact profile the FDE role screens for.
- Engineering + selling + customer relationships in one person: nobody has to
  translate between the builder and the buyer.
- Grounding proof (kept modest, evidence-not-pitch): seven years inside one
  engagement — a B2B manufacturing group that grew from $4M to $9M ARR — going from
  growth infrastructure to owning the full production AI stack. The growth happened
  because the person building the systems also understood the customers.
- Vulnerable beat: I spent years thinking the sales/PR half of my CV was the part
  to hide.
*/}
